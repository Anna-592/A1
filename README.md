# 脆弱分布错设对复发事件生存数据高维变量选择的影响 —— 模拟实验源码

本仓库提供论文模拟实验的**全部源代码、实验设计与完整结果数据**，供审稿人核查与复现。

研究问题：当复发事件数据的真实脆弱项服从 Gamma 分布，而建模时错误假定为 Log-normal（或反之），在高维（30 个协变量、仅 3 个真实信号）与强相关设计下，惩罚似然变量选择（MCP / SCAD）的变量选择性能会受到多大影响。

---

## 一、实验设计

### 1.1 数据生成（Plasmode）

- **协变量轮廓**取自 `survival::bladder2` 中 85 位膀胱癌患者的真实基线协变量（`rx`、肿瘤数量、肿瘤大小），有放回抽样得到 n 位受试者，并对两个连续变量做标准化。这样协变量的联合分布与真实临床数据一致，而非人为设定。
- **噪声协变量**：在真实 3 个信号变量之外，追加 27 个与结局无关的噪声变量，其 27 维向量服从 **AR(1)** 结构：

  $$x_{j} = \rho\,x_{j-1} + \sqrt{1-\rho^{2}}\,\varepsilon_{j}$$

  ρ 越大，噪声变量之间相关性越强，用于考察高维相关设计下的选择稳定性。

- **脆弱项**：$u_i$ 均值 1、方差 θ，真实分布可为 Gamma 或 Log-normal。
- **事件过程**：非齐次泊松过程，个体事件强度

  $$\lambda_i(t) = \Lambda_0\, u_i \exp(X_i^\top \beta),\quad \Lambda_0 = 0.6$$

  真实系数 $\beta = (1.2,\,-1,\,0.8)$ 对应 3 个信号变量，其余 27 个系数为 0。
- **随访**：观测窗口 $[0, C_i]$，$C_i \sim U\big((1-2c)\,T_{\max},\, T_{\max}\big)$，$T_{\max}=3.5$，c 为删失比例参数。
- 每个数据集整理成复发事件的**区间（start–stop）长表**，配合 `cluster(id)`。

### 1.2 72 个情景

| 因素 | 取值 | 水平数 |
|---|---|---|
| 样本量 n | 200, 400 | 2 |
| 真实脆弱方差 θ | 0.5, 1, 2 | 3 |
| 删失比例参数 c | 0.15, 0.30 | 2 |
| 噪声协变量相关 ρ | 0, 0.25, 0.75 | 3 |
| 真实脆弱分布 | gamma, lognormal | 2 |

2 × 3 × 2 × 3 × 2 = **72 个情景**（编号 s01–s72），每个情景 **100 次重复**，共 **7200 个数据集**。

### 1.3 每个数据集拟合 4 个模型

假定脆弱分布 ∈ {gamma, lognormal} × 惩罚 ∈ {MCP, SCAD}，共 4 个模型。**同一数据集、同一初始值**下比较，保证公平。

每个模型沿 **27 个调节参数** 走一条解路径：`tune = exp(seq(-5.5, 1, 0.25))`，按 **BIC** 选出最优模型。

BIC 定义：

$$\mathrm{BIC} = -2\,\ell(\hat\beta,\hat\lambda,\hat\theta) + \max\{1,\log\log(p+1)\}\cdot(\#\{\hat\beta_j\neq0\} + 1)\cdot\log(a)$$

### 1.4 随机种子

第 (sid, rep) 次重复的种子 = `20261004 + sid * 1e5 + rep`，逐一固定，任何人运行都能得到完全相同的数据集。

## 四、运行方式

### 4.1 快速验证（约数十秒）

只跑 2 个情景 × 2 次重复，用于确认环境与代码正常：

```r
setwd("仓库根目录")
source("R/01_data_generation.R")
source("R/02_gamma_engine.R")
source("R/03_lognormal_engine.R")
source("R/04_run_simulation.R")

run_simulation(scenarios = 1:2, reps = 1:2, maxit = 20000)
```

### 4.2 完整复现 72 情景

```r
run_simulation(scenarios = 1:72, reps = 1:100, maxit = 20000)
```

**计算量提示**：7200 个数据集 × 4 个模型 × 最多 27 个调节点、每点最多 20000 次 MM 迭代。单机串行需数天量级；正式运行采用多进程 + 每个参数点独立落盘断点续跑。建议按情景分批跑，例如：

```r
run_simulation(scenarios = 1:12,  reps = 1:100)   # 第一批
run_simulation(scenarios = 13:24, reps = 1:100)   # 第二批
```

`results/simulation_results.csv` 在每完成一次重复后即写盘，中断不会丢失已完成部分。

### 4.3 汇总

```r
source("R/05_aggregate.R")
```

会读取 `results/simulation_results.csv`，输出三张汇总表。

### 4.4 关于「分两批运行」与迭代上限

72 个情景 × 100 次重复的量很大，正式运行分两批完成：情景 s01–s29 为第一批（单点迭代上限 `maxit = 5000`），s30–s72 及其补跑点 为第二批（`maxit = 20000`）。中途中断只是计算预算不足，**代码本身没有改动**，可核验的两点：

1. 两批运行所用的 `gamma_code`、`worker_code`、`runner_source` 三个代码字符串的 MD5 完全一致（分别为 `92d604bb…`、`43c599ee…`、`3b7170a2…`）；两份 `formal_settings.rds` 中的 `tunes`（27 个调节参数）与 `grid`（72 行情景表）也逐项相同。
2. 两批在重叠情景（s01–s29）上的结果逐行比对，TPR、FDP、入选个数、BIC、选中的 tune **差值全部为 0**。这说明这些参数点在 5000 次以内已经收敛，提高上限不会改变结果。
3. 最终结果表里 `maxit_points`（触及迭代上限的参数点个数）**全部为 0**，即 28,800 条拟合记录中没有任何一个参数点是被上限截断的。少数早期未收敛的点（如情景 s29 的第 54 次重复）已在 20000 预算下重跑并写入最终结果，其 4 行状态均为 `ok`。

因此 `results/simulation_results.csv` 是由**同一套代码、同一组种子**产生的一致性结果；复现时把 `maxit` 设为 20000 即可，结果与仓库 CSV 一致。

数据完整性：共 28,800 行 = 72 个情景 × 100 次重复 × 4 个模型；每个情景恰好 400 行，`status` 全部为 `ok`，无缺失、无重复。

数据：7200 个数据集 × 4 个模型 = 28800 行拟合记录，全部通过数值体检（无内部异常、无触及迭代上限）。

|---|---|---|---|---:|---:|---:|---:|
| gamma | gamma | MCP | 0.9994 | 0.0487 | 3.219 | 83.67% |
| gamma | gamma | SCAD | 0.9994 | 0.0469 | 3.211 | 84.33% |
| gamma | lognormal | MCP | 0.9986 | 0.0494 | 3.219 | 83.28% |

| lognormal | gamma | SCAD | 0.9999 | **0.0920** | **3.457** | **73.53%** |
| lognormal | lognormal | MCP | 1.0000 | 0.0479 | 3.225 | 85.06% |
| lognormal | lognormal | SCAD | 1.0000 | 0.0452 | 3.213 | 86.03% |

### 5.2 配对比较（同一数据集上「错设 − 正确」，n = 3600 对）

| 真实分布 | 惩罚 | ΔTPR | ΔFDP | Δ入选个数 |
|---|---|---:|---:|---:|
| gamma | MCP | −0.0007 | +0.0007 | +0.0008 |
| gamma | SCAD | −0.0006 | +0.0021 | +0.0094 |
| lognormal | MCP | −0.0001 | **+0.0458** | **+0.2336** |
| lognormal | SCAD | −0.0001 | **+0.0469** | **+0.2439** |

**核心发现**：真实分布为 Log-normal 却按 Gamma 建模时，假阳性比例 FDP 从约 4.8% 升至约 9.3%，平均多选入 0.23–0.24 个无关变量，精确恢复率从约 85% 降至约 73%；反向错设（真实 Gamma、假定 Log-normal）影响很小。说明错设的方向性不对称，Log-normal 真实数据对 Gamma 假定更敏感。

## 六、数值实现说明（为什么需要自定义 MM 引擎）

1. **Gamma 引擎**（`02_gamma_engine.R`）：`frailtyMMpen` 内置实现用逐元素循环计算风险集与累积强度，在 30 个协变量、n = 400、区间行数上千时既慢又容易出现数值溢出。本引擎把所有风险集/累积量改为「排序 + `cumsum` + `findInterval` 查表」的向量化实现，并对 θ 更新、λ 更新、系数更新分别加数值保护（非法值回退、上界截断），保证 MM 迭代单调下降且不产生 `NaN`/`Inf`。

2. **Log-normal 引擎**（`03_lognormal_engine.R`）：Log-normal 脆弱项的对数边际似然无闭式解，每步需计算后验矩 $\mathbb{E}[e^{u}\mid\text{data}]$ 与 $\mathbb{E}[e^{2u}\mid\text{data}]$。原实现用 Laplace 近似，在强相关设计下误差累积，部分参数点迭代到上限仍不收敛。本引擎改用**自适应 Gauss–Legendre 求积**：先 24 点，与 48 点结果比对；误差超过 1e-8 则升到 96 点；仍不达标则该个体退回 `integrate()` 自适应积分。同时把后验众数求解改为带上下界保护的 safeguarded Newton。

3. **独立似然复核**：两个引擎都内置 `reference_ll()`，用与迭代路径完全独立的写法重算对数似然；每个最终模型的 $\Delta\ell$ 必须 < 1e-5，否则该参数点判为失败并记录（正式结果中失败数为 0）。

4. **初始化统一**：4 个模型共用 `capture_initialization()` 截获的同一个 `safe.ini`，避免不同起点带来的偶然差异。

5. **断点续跑**：正式运行的规模较大，程序支持只补跑尚未收敛的重复点（已完成的不重算）。仓库为便于审读，不保留检查点机制，`04` 直接输出逐条结果；对同一（情景, 重复）重算得到的数值与已有结果相同。

## 七、复现性声明

- 所有数据集均由固定种子（`20261004 + sid*1e5 + rep`）现场生成，不含任何外部数据文件，除 `survival::bladder2`（R 内置）外无其他数据依赖。
- 结果文件 `results/simulation_results.csv` 的每一行对应（情景, 重复, 假定分布, 惩罚），可由 `R/04_run_simulation.R` 按相同种子逐行重算。
- `R/05_aggregate.R` 对本仓库的 CSV 运行后，可直接得到第 5 节两张表（数值逐项一致）。
- **引擎等价性**：`R/02`、`R/03` 的 MM 更新与正式运行所用的原始实现做过逐步数值对照——在同一初始状态、同一惩罚参数下执行一步更新，系数向量、θ（脆弱方差）、基线强度 λ、对数似然的**差值均为 0**（`max |Δ| = 0`），说明仓库里的实现不是近似替代，而是与原实现的等价重写。
- **选择规则一致性**：最终模型取参数路径上 BIC 的全局最小值（`which.min(path$BIC)`），不额外附加「该点通过筛查」的限制；BIC = `−2ℓ + max(1, log(log(p+1))) × (非零系数数+1) × log(受试者数)`；入选阈值为 `|coef| > 1e-8`；TPR = 真实信号被选中的比例，FDP = 被选入的噪声变量数 / max(1, 入选总数)。以上均与正式运行所用程序一致。
- **逐行复现**：用本仓库 `R/01`–`R/04` 重跑情景 s01 的第 1 次重复（种子 20261004 + 1×1e5 + 1），4 个模型的 TPR、FDP、入选个数、BIC、选中 tune 与 `results/simulation_results.csv` 中对应 4 行**完全相同**（差值 0），单次重复耗时约 1.3 分钟，可作为复现性自检的最小样例。
- 单情景最小复现：

```r
run_simulation(scenarios = 61, reps = 1)   # 情景 s61 = 真实 lognormal, n=200, theta=0.5, c=0.15, rho=0.75
```
